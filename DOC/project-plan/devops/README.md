# DevOps

## Purpose

This folder defines the environment model, build pipeline, deployment strategy, and post-deploy validation for the Plumbing Template. Deployment target is Vercel (default for Next.js; zero-config for App Router).

---

## Environment Model

| Environment | Trigger | Env Vars | Notes |
|---|---|---|---|
| Local | `npm run dev` | `.env.local` | `RESEND_API_KEY` optional; fail-soft active |
| Preview | Vercel PR deploys | Vercel env group (preview) | Automatically deployed per branch/PR |
| Production | Merge to `main` | Vercel env group (production) | Manual promotion after QA gate |

---

## Build Pipeline

```
npm run build
```

Expected output:
- Zero errors
- Zero warnings (strict: no missing page warnings, no invalid link warnings)
- All static pages generated at build time
- `generateStaticParams` for `/services/[slug]` produces 8 pages

---

## Secrets and Config Isolation

| Variable | Local | Preview | Production |
|---|---|---|---|
| `RESEND_API_KEY` | `.env.local` | Vercel preview env | Vercel production env |
| `BOOKING_TO_EMAIL` | `.env.local` | Vercel preview env | Vercel production env |

- Never commit `.env.local` — verify Next.js default `.gitignore` covers it
- Provide `.env.example` in repo root with placeholder values
- No `NEXT_PUBLIC_` prefix on secrets — they must remain server-only

---

## Deployment Steps (Vercel)

1. Connect GitHub repository to Vercel project
2. Set production env vars in Vercel dashboard
3. Deploy: `git push origin main` triggers automatic Vercel production build
4. Run post-deploy validation checklist (see QA doc)

---

## Preview Deploy Strategy

- Every branch push creates a Vercel preview URL
- Preview deploys use preview-tier env vars (can point to test Resend account or no-op)
- Share preview URL for review before merging to main

## Rollback Strategy

Vercel instant rollback:
- Vercel Dashboard → Deployments → previous build → "Promote to Production"
- Target: rollback within 2 minutes of a bad deploy

---

## Post-Deploy Validation

See [qa/README.md](../qa/README.md) for the full verification checklist. Minimum post-deploy steps:

1. Visit production URL — home page loads
2. Click every nav link — zero 404s
3. Submit booking form — success state renders
4. Visit `/sitemap.xml` — all routes present
